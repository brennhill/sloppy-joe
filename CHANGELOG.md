# Changelog

## Unreleased

- Build: update `tokio` to 1.53.3 (RUSTSEC-2026-0386, `AsyncFd` I/O-safety, affected 1.49.0), and allowlist the `sha1`, `flate2`, `tar` and `semver` crates in the repository's own self-check config so the CI self-check does not flag them as typosquats.
- Cargo: trust `Cargo.lock` for a ranged crates.io requirement (`serde = "1.0"`) when exactly one locked version satisfies it, using the `semver` crate (pinned `=1.0.28`) for Cargo's requirement rules. A lock that contradicts the requirement is `resolution/lockfile-out-of-sync`, several satisfying versions stay `resolution/ambiguous`, and an invalid requirement keeps `resolution/no-trusted-lockfile-sync`. This amends `docs/specs/cargo-provenance-hardening.md`; real projects such as `bat` and `fd` now scan cleanly. Other ecosystems keep the strict rule.
- Maven: derive versions the way Maven's effective model does. `${property}` references, `<dependencyManagement>` and `<pluginManagement>` entries, imported BOMs, and the `<parent>` chain (local reactor parents, otherwise POMs fetched from Maven Central) now supply versions, so Apache-style projects that manage plugin versions in a parent no longer block with `resolution/no-exact-version`. A parent or BOM that cannot be fetched fails the scan; a version that cannot be derived stays unresolved.
- Red-team round 6: JS workspace members that discovery cannot bind (a `package.yaml`/`package.json5` manifest, or a directory in `ignore_dirs` such as `.planning`) now block the scan instead of being installed from the workspace lockfile unscanned. requirements.txt now ends a backslash continuation at a blank or comment line like pip does, so a requirement after it is no longer swallowed, and a PEP 263 coding line for an encoding other than UTF-8/ASCII/Latin-1 is rejected because pip would decode the file differently. pnpm lockfiles containing YAML merge keys (`<<`) are rejected, since pnpm expands them and sloppy-joe does not.
- Red-team round 6, continued: Bundler's `gems.rb` / `gems.locked` now block instead of being skipped in a multi-project repo. Scanning a Cargo workspace member directory below an outer `[workspace]` root is refused (cargo would use the root's `Cargo.lock` and `.cargo/config.toml`); scan the workspace root instead. `composer.lock` `dist.url` / `source.url` must be https URLs on Packagist, GitHub, GitLab or Bitbucket hosts. .NET projects now block on `RestoreSources`, `RestoreAdditionalProjectSources`, `RestoreFallbackFolders`, and a `nuget.config` (project directory or any parent) whose package sources are not nuget.org.
- Similarity: package names longer than 214 characters now produce a blocking `similarity/name-too-long` error instead of being expanded into thousands of registry probes.
- Registries: an HTTP 429 is now repeated (up to 5 attempts, honoring `Retry-After`, each wait capped at 10 seconds) before it counts as a failure. A persistent 429 still fails closed. A scan of this repository's 221 crates against a throttling crates.io went from 212 existence errors to 11.
- Maven registry: when search.maven.org refuses or cannot answer (HTTP 403, 429 or 5xx, or a network error), existence and publication dates now come from Maven Central's repository layout itself (`maven-metadata.xml` and the POM's `Last-Modified`). Previously every Maven lookup failed or came back unparsed while the search API returned 403. A lookup failure in the metadata-based existence check now says the lookup failed instead of claiming the package does not exist; it still blocks.
- Maven (red-team round 5): the effective model now matches Maven where a crafted POM could hide a version. Dependencies and plugins inherited from a local or remote parent (and the grandparent coordinate) are scanned; XML comments are ignored; a decoy `<version>` inside `<exclusions>` no longer shadows the real one; duplicate `<properties>`, `<dependencies>`, `<build>` and similar sections block instead of picking one; a profile property or managed version that differs from the base is scanned as an additional candidate version (which profile is active depends on the build), a profile-only value stays unresolved, and `.mvn/maven.config` `-D` overrides, leave the version unresolved; classifier/type-qualified management entries no longer shadow plain ones; plugin management never versions a dependency and vice versa.
- Maven: a `${property}` version that cannot be resolved is now unresolved instead of being treated as a literal version string. Previously the placeholder was sent to OSV as the version, so a vulnerable dependency declared through a property was not reported.
- pnpm: accept in-repo directory packages (`name@file:dir` with `resolution: {directory: dir, type: directory}`), which pnpm records for `file:` dependencies and which have no integrity hash. They are no longer rejected as untrusted registry entries or looked up in the registry; a directory that is absolute, climbs with `..`, or does not match its lockfile key still blocks.
- Ruby: support `gemspec` in a Gemfile (`gemspec`, `gemspec name: "x"`), the standard layout of a gem's own repository. The dependencies of the matching `.gemspec` are scanned from literal `add_dependency` / `add_runtime_dependency` / `add_development_dependency` calls; a missing or ambiguous gemspec, redirecting options such as `path:`, and any dynamic dependency declaration still block.
- Ruby: accept `if` / `unless` / `elsif` / `else` blocks and trailing `if` / `unless` modifiers around gems when the condition is a simple comparison. Every branch is scanned, so the condition cannot change what is verified; conditions that call `gem`, run commands, touch files or span lines still block.
- Gradle: scan `buildscript { dependencies { classpath '...' } }` artifacts, which run in the build but never appear in `gradle.lockfile`. Each must pin a literal version (no `+`, `latest.*`, ranges, or missing version), is checked for existence and advisories against Maven Central (plus Google's repository when the `buildscript` block lists `google()`), and `classpath files(...)`, `project(...)`, `platform(...)` and version-catalog references still block. Only `mavenCentral()` and `google()` are accepted in `buildscript { repositories {} }`.
- Gradle: support a plain `google()` repository (Android builds). Dependencies are then checked against Maven Central and Google's Maven repository, which count as existing if either serves them, with publish dates from the POM `Last-Modified` header. `google { }`, `google(...)` with arguments, `maven { }` and other repository forms still block.
- Gradle: look up OSV advisories for the implementation artifacts a `plugins {}` marker delegates to (read from the marker POM's dependencies), not just the marker. A marker POM that cannot be read, or that names a dependency whose version is missing, a property, or a range, blocks.
- Config: validate `trusted_registries.jvm` entries. The name must be `gradle-plugins` (the only name sloppy-joe reads) and the source a credential-free https URL, so a typo no longer leaves a repository silently untrusted.
- pnpm: read multi-document `pnpm-lock.yaml` files, which pnpm writes when it manages its own version (`packageManagerDependencies`). The last document is the project lockfile; the packages of earlier documents must be plain registry entries with integrity hashes and are scanned as transitives of the root. More than four documents, a malformed document, or a non-registry env package blocks.
- pnpm: resolve transitive packages by their locked `name@version` instead of demanding an importer entry, which wrongly reported `resolution/missing-lockfile-entry` for every transitive in a full scan.
- Python: accept `-e .` and `-e .[extras]` (also `--editable`) in requirements files when the project's own `pyproject.toml`, `setup.py` or `setup.cfg` sits next to the file. Its dependencies are scanned from that manifest, so the line adds nothing to verify. Editable paths, URLs and VCS targets still block.
- Poetry: match lockfile artifact filenames to packages by normalized name, so projects whose files keep the original punctuation (`jaraco.classes-3.4.0-...` for `jaraco-classes`) are no longer downgraded to reduced confidence and flooded with `resolution/no-exact-version` errors. The version must also end exactly where the wheel tag or sdist extension begins, so `requests-1.0.1` no longer counts as `1.0`.
- Poetry: scan every locked version when a root dependency has several entries from Python-version splits in `poetry.lock` (for example `platformdirs` 4.12.4 and 4.13.0), instead of rejecting the project as ambiguous. A split where any candidate comes from a non-default source still fails closed.
- Python: accept PEP 508 version specifiers written in parentheses (`poetry-core (>=2.1.0,<3.0.0)`), which Poetry 2 projects emit, instead of rejecting them as an invalid package name. Unbalanced parentheses are still rejected.
- Pipenv: check `Pipfile.lock`'s `_meta.hash` against the Pipfile using pipenv's own algorithm (validated against real published locks). A lock generated from a different Pipfile now blocks as out of date, and a missing `_meta.hash` blocks. Pipfiles holding values pipenv's hash cannot reproduce here (floats, datetimes) keep the package-level reconciliation only.
- Pipenv: read a version with no comparison operator (`version = "26.2.*"`, `requests = "2.32.3"`) as `==`, as pipenv does, instead of rejecting the Pipfile with an invalid package name.
- Go: verify the contents of `go.sum`, not just its presence. Every `require`d module version needs a well-formed `<version>/go.mod` checksum, conflicting duplicate hashes and malformed lines block, and a PR can no longer add a requirement without a recorded checksum. Vendored projects (`vendor/modules.txt`) are exempt because Go ignores `go.sum` there.
- Python `setup.cfg`: block a non-empty `dependency_links`, any `[easy_install]` setting, and unrecognized dependency-looking `[options]` keys instead of silently ignoring them. Metadata and packaging options are still ignored.
- bun.lock: resolve dependencies from the nearest nested entry (`parent/child`, `member/child`) before the top-level copy, as Bun installs them, so a nested version can no longer be swapped for the hoisted one; accept nested keys whose last segment matches the locked package and block malformed ones. When bun.lock has no root workspace, every workspace scans entries nothing reaches.
- Pipenv: reconcile a committed `Pipfile.lock` with the Pipfile in both directions. Every package in `[packages]`, `[dev-packages]`, and custom categories must be locked in the matching section with an exact `==` pin and hashes, and must satisfy its Pipfile specifier; lock-only entries are scanned as transitive dependencies at their locked versions. Entries from `git`/`path`/`file`/`editable` sources or a non-PyPI index, and lock sources outside `trusted_indexes.pypi` or not declared in the Pipfile, block.
- Scan the lockfile of a project whose manifest declares no dependencies instead of skipping it: npm, pnpm, Yarn, Bun, Cargo, Bundler, Composer, Poetry and uv lockfile packages are now validated and scanned (or flagged as stale), and Gradle/NuGet lockfiles with packages still block. pnpm now reports packages no importer reaches as `lockfile/orphan-entries` warnings for a standalone lockfile and scans them from the root importer of a workspace or when the graph cannot be fully resolved.
- Python `setup.py`: block keywords that can carry or redirect dependencies but were silently skipped: a non-empty `dependency_links`, `options` with `easy_install` settings, plugin or unknown keywords such as `pbr=True`, and repeated keywords. Malformed `extras_require` and dependency lists now report `Scan not supported`.
- Python: check `--index-url`, `-i`, and `--extra-index-url` in every scanned requirements file (not only hash-locked ones), including `-r`/`-c` includes, against `trusted_indexes.pypi`. A non-PyPI index that is not allowlisted now blocks with a `resolution/untrusted-registry-source` error naming the index and the declaring file. Previously an unhashed requirements file could point pip at another index while sloppy-joe vetted the public PyPI package.
- Ruby: parse `gem` entries with several version requirements (`gem 'x', '~> 1.0', '>= 1.0.2'`) instead of blocking them as unsupported. Every requirement is kept; a malformed or dynamic one still blocks.
- Gradle: check third-party `plugins {}` requests instead of blocking them all. Each request resolves to its plugin marker artifact (`<id>:<id>.gradle.plugin`) with a literal id and exact version (explicit, `kotlin("x")`, `libs.versions.toml` alias, `pluginManagement` default, or enclosing build script) and is checked for existence, version publication, release age, and package age against the `pluginManagement` repositories (default: Gradle Plugin Portal; `mavenCentral()` supported). Look-alikes of well-known plugin ids are flagged. Dynamic or unresolvable plugin versions and ids still block. Custom plugin repositories block unless allowlisted under `trusted_registries.jvm`; plugins of an allowlisted repository are reported as unvetted.
- Python: scan every dependency group and extra by default (Poetry groups, PEP 735 `[dependency-groups]`, uv dev dependencies, optional dependencies; PDM/Hatch environments as unlocked tooling). `--python-groups`/`--python-extras` now narrow the selection and warn about the groups and extras they exclude. Resolve PEP 735 `include-group` entries, blocking on cycles, unknown groups, and malformed include tables.
- uv.lock: read root `optional-dependencies`, `dev-dependencies`, and `requires-dev`, follow locked package extras transitively, and check lock and manifest in both directions. A locked root dependency/extra/group entry missing from pyproject.toml, or a declared group dependency missing from uv.lock, now blocks.
- Verify npm tarballs against registry metadata for new, recent, low-download and flagged versions (all versions with `--paranoid`): hash-check the tarball, read its `package.json` under size limits, and block when its install scripts or dependencies differ from the registry metadata. Download, hash and limit failures for a selected version block instead of being skipped.
- NuGet: read publish dates from the SemVer 2.0.0 registration hive (`registration5-gz-semver2`) so SemVer 2.0.0-only packages get metadata and version-age checks. Follow paged registration indexes (bounded), keep every page on the NuGet host with no redirects, decompress gzip under a hard size cap, and fail closed on malformed registration data. Unlisted versions no longer pass the age gate with NuGet's 1900 placeholder date.
- Make the per-scan npm tarball verification limit configurable with `max_npm_tarball_verifications` (1-1000, default 100) in the out-of-repo config. Versions past the limit still block, and the finding now states how many selected versions went unverified.
- Compare the integrity recorded in npm, pnpm, Bun and Yarn classic lockfiles with the registry packument's `dist.integrity`/`dist.shasum` for every checked npm package. A different hash blocks with `metadata/lockfile-integrity-mismatch`; a missing lockfile hash or no shared hash algorithm blocks with `metadata/lockfile-integrity-unverified`.
- Mark a typosquat finding HIGH CONFIDENCE only when the dependency has few downloads and the package it resembles has many; the reverse is noted as LOW CONFIDENCE without lowering severity.

- GitHub Action: download and extract the release in a fresh temp directory, verify the archive against its published `.sha256`, and never install or put on PATH files from the PR checkout.

- Reject unknown and duplicate keys in sloppy-joe config and local overlay files instead of silently ignoring them.

- Reject cache directories inside the scanned repository (or scan root), including symlinked and not-yet-created paths, and ignore relative `XDG_CACHE_HOME`/`HOME` values; committed cache files can no longer forge OSV or similarity results.

- Report `yarn.lock` entries no dependency reaches as a non-blocking `lockfile/orphan-entries` warning instead of leaving them silently unscanned; when reachability is uncertain (workspace roots, unresolved edges), scan them instead. Block yarn and pnpm lockfile entries with invalid package names and duplicate `yarn.lock` selectors, and resolve Yarn transitive dependencies by their locked identity.

- In `--ci`, block repository `.npmrc` registry routes not allowlisted under `trusted_registries.npm` in the out-of-repo config. Routed package names stay private: they are never sent to the public registry or OSV.

- Reject transitive npm links to external, unscanned, or incorrectly named local targets before a full scan can pass or save a success fingerprint.
- Resolve npm workspace dependencies from the member directory upward, preserve nested versions in vulnerability checks, and use the same lookup for aliases and local links.
- Check ancestor workspace membership before validating manager conflicts, so unrelated parent errors do not suppress independent child scans.

- Scan independent install roots in mixed-manager repositories without treating an incomplete ancestor npm/pnpm workspace declaration as authoritative.
- Report each project and its lockfile separately, retain completed sibling results when another project is unsupported, and return exit 2 for incomplete repository scans.
- Keep registry routing scoped to the selected install root and preserve each chain's direct and transitive version selections.

- Ignore `.planning` during recursive project discovery by default; add the external-policy `ignore_dirs` setting for custom directory exclusions.

- Support default and scoped HTTPS npm registry routing in project-local `.npmrc` for npm and pnpm.
- Report private/custom-registry packages as unvetted with non-blocking warnings; retain public package checks and local lockfile/source validation.
- Keep private identities and authentication values out of public registry/advisory requests, and redact rejected registry source credentials.
- Invalidate scan guidance when effective registry routing changes.
- Resolve npm workspace dependency ranges from the authoritative root lockfile.

## 1.2.0

### Security and correctness

- Close dependency parsing and source-policy bypasses across Python, JavaScript, Ruby, Go, JVM, Cargo, and .NET projects.
- Preserve trusted policy boundaries when scanning subdirectories or relative paths.
- Keep metadata and vulnerability checks active for transitive dependencies and respect cache selection and bypass options.
- Reject future-dated security caches, preserve cache expiry on reuse, and record successful full scans only after passing checks.
- Enforce version-age policy when publication dates are missing or invalid, and account for timezone offsets.
- Bound package-name lengths before typo mutation generation.
- Avoid reporting Cargo hyphen/underscore spellings of the same crate as typosquats.
- Discard invalid generated package names before similarity queries instead of misreporting them as registry outages.
- Accept legacy registry UTC publication timestamps while preserving timezone-aware age checks.
- Include legacy Python build and test dependencies.
- Recognize packaged uv project roots and uv lockfiles without redundant tool metadata.
- Verify supported uv version ranges against exact locked selections instead of requiring redundant manifest pins, using PEP 440 parsing for prerelease, postrelease, and local versions.
- Follow OSV advisory pagination and reject malformed or incomplete query responses.
- Separate maintenance-only unmaintained notices from vulnerability records; retain blocking unsoundness advisories.
- Update affected direct and transitive dependencies to patched versions before release.
- Refresh README coverage against primary-source supply-chain incident reports and document heuristic limits.

### Compatibility notes

- Inputs whose dependency graph or source policy cannot be verified report an unsupported scan (exit 2).
- Legacy setup.py scanning accepts a restricted literal grammar. Executable setup logic, computed arguments, and custom source encodings are unsupported.
- Package names are limited to 214 bytes for npm and 1,024 bytes for other ecosystems.
